# 1年8組 — 固定ブロック方式のブラウザゲーム

## 起動と操作

このフォルダの **index.html** をブラウザで開くだけで動きます。HTML / CSS / JavaScriptのみを使い、サーバー、インストール、外部ライブラリ、通信は不要です。
スマートフォンは横画面を推奨します。ローカルHTMLのJavaScriptを実行できるブラウザで開いてください。

- PC：← / →で移動、扉付近で↑を押すと入室。Dでデバッグ表示。
- スマートフォン：◀ / ▶を長押しして移動、「入室」をタップ。
- 遊び方を開くと一時停止。Escまたは「歩き続ける」で再開。
- 正式タイトルの「はじめる」はクリック、タップ、Enter（Return）で開始します。ENDの行追加・ページ送りはクリック／タップ／Enter（Return）。最後のEND表示後、クリック／タップ／Enter（Return）または「タイトルへ戻る」で戻ります。

1年1組より手前の何もない壁ゾーンから、自分の教室「1年8組」を目指します。下駄箱は描画しません。異変がなければそのまま進み、異変があれば来た方向へ引き返します。
途中の方向転換は回答になりません。ブロックの端を主人公全体が抜けた時だけ判断が確定します。
結果メッセージやクラス番号のHUDはなく、各教室の後扉のプレート「1-1〜1-8」で、その教室へ到達したことを確かめます。
NORMALの8組へ進行方向に歩き、プレート付き後扉付近で入室するとENDです。1〜7組へ入室すると、そのプレイで初めて入った教室の順に記憶1〜7が割り当てられます。8組は既読状況に応じて通常END／真ENDに分岐します。

## 新しい進行システム

**クラス番号は座標ではなく進行状態です。** 1〜8組を大きな廊下上へ事前配置しません。
毎回、1クラス分の同じテンプレートを現在の進行方向に合わせて生成します。

基本構造は、教室ゾーン → 独立した壁ゾーン → 教室ゾーン → 壁ゾーンの繰り返しです。
意味上の構成は、プレートなし前扉 → 窓 → 窓＋向かい合う女子2人 → 窓 → プレート付き後扉 → 壁の余白 → 掲示板＋男子1人 → 境界としての柱です。
判定地点周辺には扉・窓・掲示板・NPCを置きません。蛍光灯は区画とは独立した建築設備として、壁ゾーンを含め廊下全体に400px間隔で並びます。
窓3枚、扉2枚、掲示板1つ、区画終端の柱1本。全クラスで長さ、配置、間隔、NPCの人物と位置・行動は固定です。
左向きブロックではテンプレート全体を反転し、文字だけは読みやすい向きを保ちます。左右どちらでも進行方向に対して同じ順序になります。

`rules.js`が管理する状態：

| 状態 | 用途 |
| --- | --- |
| `LAST_CLASS` | 最終クラス番号（8）。UIは`WORLD.finalRoom`経由で参照 |
| `CORRIDOR` | 全クラス共通の変更不可テンプレート。教室と壁の領域は`zones`で明示 |
| `currentRoom` | 現在向かっているクラス。正解で1増え、8組では8を維持。不正解で1になる |
| `active` | 現在ブロックのID、進入端`anchor`、進行方向、クラス、異変、`judged`、後扉への到達`finalArrival`、経過時間・最遠観察位置 |
| `inBlock` | 開始壁ゾーンの導入を終えてブロックに入ったか |
| `entranceClosed` | 開始導入を一度離れたか。従来の状態名だけを維持し、下駄箱描画は廃止 |
| `lastDecision` | 直前に確定した判断。通常プレイには表示しない |
| `trailing` | 境界付近の描画を継続するための直前ブロック1つ |
| `x` / `worldOffset` | 原点移動後の描画座標と、移動距離を保つ累積オフセット |

`Run.move()`は、進行側または進入側の判定地点を抜けたかで正誤を判定します。主人公の半幅25pxも含めて抜けた時点で1回だけ確定します。教室ゾーンを抜けただけでは確定しません。
新ブロックの進入端は抜けた境界、進行方向は実際に抜けた左右の方向です。引き返した場合も過去ブロックへ戻らず、新しいIDと異変状態を持つブロックが生成されます。
直前のブロックは描画専用で、入室・判断の対象ではありません。それ以前の履歴は捨てるため、保持するブロックは最大2つです。

進行の管理単位は判定地点から次の判定地点までの3,700pxです。開始壁ゾーンの導入は900px、移動速度は250px/秒を維持しています。
配置された区画は約990〜3,145pxで、判定位置3,700pxは従来どおりです。その前後に設備のない視覚的バッファを保ちます。ブロック長3,700pxを変えないため、区画を詰めた分の残余距離は境界側と進入側の余白に割り当てます。
画面幅960pxに対して必要な分だけ壁を確保し、判定の前後では教室設備を画面外に置きます。壁の柱は判定地点から±160pxの位置に固定し、方向転換やブロック交換でも動かしません。通常進行時の壁の通過は約4.5秒、教室ゾーンは約10.3秒です。
次の教室を先に描画する処理は取り除きました。実際のブロック生成・異変抽選・クラス進行は従来どおり、主人公全体が判定地点を抜けた時だけ発生します。各教室の配置は左右の進行方向に合わせて同じ描画を反転します。壁の柱は描画専用で、過去の教室を保持したり進行を変えたりしません。
境界では主人公、ブロック、カメラの座標原点をまとめて移すため、画面上の位置・床の継ぎ目・長押し入力を保ったままつながります。暗転・フェード・ロード画面はありません。
クラス番号と座標には対応関係がなく、描画座標も一定範囲に収まります。

## 異変と正常状態

最初の1組ブロックは必ず正常で、異変の乱数を一度も使いません。失敗後に生成される1組は通常の抽選対象です。下駄箱は開始時を含めて表示しません。
以後の1〜8組はNORMAL（異変なし）50%、異変50%。異変ありの場合は下記10種類から等確率で1種類だけ選びます。`config.js`の`anomalyRate`（0〜1）で発生率を変更できます。現在は各異変5%です。

| 番号 | ID | 名称・表示場所 |
| --- | --- | --- |
| ANOMALY 01 | `hole` | 教室ゾーン内の床に大きな穴 |
| ANOMALY 02 | `dog` | 後扉付近の廊下に静止した犬1匹 |
| ANOMALY 03 | `light` | 選択されたブロック内の全電灯が破損・消灯 |
| ANOMALY 04 | `girlsLooking` | 中央窓の女子2人が廊下・主人公側を正面に見る |
| ANOMALY 05 | `boyLooking` | 掲示板の男子が廊下・主人公側を正面に見る |
| ANOMALY 06 | `blood` | 教室ゾーン内の床に血痕 |
| ANOMALY 07 | `handprint` | 最初の窓のガラスに血の手形 |
| ANOMALY 08 | `deathNotice` | 既存掲示板が血文字の「死」になる |
| ANOMALY 09 | `knife` | 3枚目の窓と後扉の間の床に血の付いた包丁 |
| ANOMALY 10 | `brokenWindow` | 3枚目の既存窓ガラス1枚の破損 |

構造物の数・中心座標・間隔は異変時にも変えません。床の穴・犬・包丁などは描画だけで、当たり判定、落下、拾う操作はありません。電灯・窓の枠は残し、状態を変えます。NPCは人数・位置・身長スケールを維持します。人物異変は提供された正面・青白い顔の差分PNGへ置き換えます。主人公側を見る異変は固定の正面姿で、移動に追従するアニメーションは行いません。壁ゾーンには異変を置きません。
ブロック生成時に1回だけ抽選し、何度往復しても抽選し直しません。正常NPCは歩き回らず、通常背景にも乱数を使いません。
8組も通常の抽選・境界判定を行います。異変時に引き返して境界を抜けると8組を再生成し、前進して境界を抜けると1組へ戻ります。NORMALで戻る場合も誤答です。NORMALの8組は前方のブロック端で停止し、8組を再生成しません。停止後も後扉へ戻って入室できます。NORMALの8組へ進行方向に歩き、後扉の75px以内に到達すると`active.finalArrival`が成立します。`canEnterFinal`が8組・NORMAL・到達済み・後扉付近・プレイ中を満たす場合だけ、↑または入室ボタンで成功を確定してENDになります。自動クリアは行いません。異変時は入室できず、前進の誤答確定は従来どおり壁ゾーンの判定境界です。

異変の選択・保持は既存の`rules.js`の`ANOMALIES`を使用します。画像の表示設定は`art.js`の`ANOMALY_VISUALS`にIDごとにまとめ、対象`target`、素材`asset`、描画方法`mode`、床画像の幅・高さ・Y位置を管理します。画像ファイルと透明余白の切り出しは`ASSETS`に登録します。番号`code`は従来の定義順を維持します。
設備の差分は通常と同じ表示矩形に置き換えます。人物は同じ中心座標・足元・身長を使用し、床の画像だけ通常背景に重ねます。提供された窓・掲示板の差分は枠を含む完成画像なので、二重に重ねず差し替えます。1ブロックで選択されたIDの表示だけを使用し、進行コードへ種類ごとの分岐を追加しません。
今回はすべて`static`で、時間によって形や位置を変えません。ブロック状態の`elapsed`（滞在時間）と`furthest`（最遠観察位置）は、今後動的・環境異変を追加する足掛かりとして維持しています。
ポーズ中は経過時間も止まります。今後音・環境変化を追加する際も、異変選択を移動方向や描画フレームで再抽選しないでください。

## 異変のデバッグ確認

コードで固定する場合は`game.js`先頭の`FORCE_ANOMALY`を指定して再読み込みします。通常プレイは`null`です。`"NORMAL"`または`"light"`、`"brokenWindow"`、`"handprint"`、`"deathNotice"`、`"blood"`、`"knife"`、`"hole"`、`"dog"`、`"girlsLooking"`、`"boyLooking"`を指定できます。初回1組のみNORMAL固定です。8組も強制指定できます。既存のDキーの選択欄も利用できます。

PCでDを押すと、現在のNORMAL／ANOMALY 01〜10、名称、クラス、方向、ブロック内位置、直前の判定を確認できます。通常時は情報と操作パネルを隠します。

1. 最初の正常な1組を通過し、2組以降でDを押します。
2. 右上の選択欄でNORMALまたは任意の異変を指定します。指定は次ラウンド以降に適用され、現在のラウンドには影響しません。
3. すぐ確認する場合は「指定状態でこのラウンドを再生成」を押します。同じクラス・位置・方向のまま、新しいIDの検証ラウンドを生成します。進行判定は行いません。
4. 選択した対象まで歩いて確認し、引き返す／そのまま進む操作を試せます。
5. Dで閉じると次ラウンド以降は通常抽選へ戻ります。現在の選択状態は終了まで維持します。

初回1組だけNORMAL固定で、再生成できません。8組は強制指定・再生成でき、再生成時に到達状態はリセットされます。選択欄の操作中は矢印キーで主人公を動かしません。

```sh
node tests/rules.test.cjs
node tests/runtime.test.cjs
node tests/endings.test.cjs
```

## PWAとホーム画面への追加

`manifest.webmanifest`に「1年8組」、`start_url` / `scope` / `id`: `./`、`display: standalone`、`orientation: landscape`、黒いテーマ／背景、192・512pxのPNGアイコンを設定しました。アイコンは`assets/images/app_icon.png`（1254×1254）を加工せず縮小しています。180pxのApple Touch Iconと32pxのfaviconも用意しています。「8」の切れを避けるため`purpose: any`を使用し、角丸・余白・トリミングを追加していません。

### ゲームバランス設定

今後の数値調整は`config.js`だけを編集し、ページを再読み込みしてください。公開版では編集後にSiteへの反映が必要です。

- `walkSpeed`：現在の250px/秒に対する倍率。初期値1.0。1.2なら300px/秒、0.8なら200px/秒。0なら移動しません。`baseWalkSpeed`は既存の基準値250です。
- 歩行周期：既存120msを速度倍率で割ります。速度1.2なら1コマ100ms。6枚の順序・停止時idle・左右反転は同じで、足音も表示フレーム01／04に同期します。
- `anomalyRate`：通常ラウンドの異変発生率（0〜1）。初期値0.5。最初の1組NORMAL固定とデバッグ強制指定は維持し、8組も通常ラウンドと同じ抽選です。
- `anomalyWeights`：全10種類のID別相対ウェイト。初期値は全て1。0なら通常抽選から除外。小数も利用でき、合計100にする必要はありません。未登録・負数・非数値は抽選対象外です。全て0ならNORMALになります。異変の通常出現確率は`anomalyRate × そのウェイト / 有効ウェイト合計`です。
- `masterVolume`、`ambientVolume`、`footstepVolume`、`doorVolume`、`lightVolume`、`chimeVolume`：初期値全て1.0。0＝無音、1＝現在の聞こえ方に対する倍率です。既存の音量調整を保持するため、実音量は`baseVolumesの基準音量 × masterVolume × 各カテゴリ倍率`（最終値0〜1）です。例えばマスター0.8、足音0.5なら現在の足音の40%となり、実音量は0.28×0.8×0.5＝0.112です。
- `baseVolumes`：元音源に対する基準音量（0〜1）。絶対値で調整したい場合もこのファイル内で変更できます。

初期値では進行・描画・音量・歩行周期が従来と同じです。設定変更によってブロック内の異変が再抽選されることはありません。`config.js`はブラウザで他のゲームスクリプトより先に読み込み、PWAの主要キャッシュにも含めています。

設定テスト5項目と速度変更時の歩行／足音同期テストを追加しました。既存127項目と合わせて133項目が通過しています。

### 開始時の遊び方

タイトルの「はじめる」でチャイムを一度再生し、遊び方を1画面表示します。「ゲーム開始」のクリック・タップ、Enterで既存の本編初期化処理を実行します。説明中は本編を開始せず、移動・時間更新・判定も停止します。チャイムの再生は継続し、本編開始時に再生し直しません。タイトルから開始するたびに表示します。

文章の変更は`howToPlayData.js`の`title`（見出し）、`lines`（段落ごとの文字列配列）、`buttonText`（開始ボタン）を編集してください。HTMLとして解釈せず、文字として表示します。ゲーム中の「遊び方」ボタンでも同じ文章を表示し、「閉じる」で本編へ戻ります。PWAの主要キャッシュにもデータファイルを含めています。

遊び方の文字サイズも`howToPlayData.js`で設定できます。`titleSize`・`bodySize`は通常画面、`mobileTitleSize`・`mobileBodySize`は横画面かつ高さ600px以下の画面向けで、単位はpxです。見出しの`titleSize: null`は従来の30〜48px自動調整を維持し、数値（例：36）にすると固定サイズになります。本文13px・横画面見出し28px／本文11pxが初期値です。開始時とゲーム中の遊び方の両方へ適用されます。

### タイトルの共有

`shareData.js`の`title`・`text`を編集すると共有内容が変わります。`url`が空なら現在のURLから不要なクエリ・ハッシュを除去し、固定URLを指定すると優先します。タイトルの「共有」でWeb Share APIを直接呼び出し、キャンセル（AbortError）では何も通知しません。API非対応・その他の失敗時は、X／LINE／リンクコピー／閉じるのダイアログを開きます。SNSリンクは投稿・送信の確定を行わず、ユーザーが投稿画面で確認する方式です。

コピーはClipboard APIを優先し、利用できなければ旧ブラウザのコピー処理、それも失敗した場合は選択できるURL欄を表示します。保存データ・音声・本編進行には触れません。`share.js`に共有処理を分離し、タイトルのみから利用します。LINEのリンク形式は[公式ガイド](https://developers.line.biz/ja/docs/line-social-plugins/install-guide/using-line-share-buttons/)に合わせています。

共有の確認：既存テストと`tests/share.test.cjs`はすべて成功。ChromeのPC・844×390タッチ操作で独自メニュー、実際のClipboard API、SNSリンクの内容、標準共有APIの代替によるキャンセル、既存の本編開始を確認済みです。OS共有シートの操作、LINE実機での送信、Xの投稿確定は行っていません。
