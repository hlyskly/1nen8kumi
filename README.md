# 1年8組

HTML / CSS / JavaScriptで動く2D横スクロールゲームです。外部ライブラリやビルド処理は使いません。

## 公開・開発

- リポジトリ：`hlyskly/1nen8kumi`、ブランチ：`main`
- 公開先：https://hlyskly.github.io/1nen8kumi/
- 修正後に自動テストと必要な画面確認を行い、正常ならcommit・mainへpushします。GitHub Pagesの自動更新後、公開反映も確認してください。
- 作業前に`git status`を確認し、未コミットのユーザー編集を上書きしないでください。テスト失敗・未解決のエラー・意図不明な変更がある場合はpushしません。
- ChatGPT Sitesは使用しません。旧公開用フォルダ`sites-preview/`は使用・編集・削除しません。

ローカル確認は、このフォルダをHTTPで配信します。

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

ブラウザで http://127.0.0.1:8765/ を開きます。`index.html`を直接開く方式でも本体を遊べますが、音声とPWAの確認にはHTTP環境を使用してください。

## 操作と開始の流れ

- PC：← / →で移動、扉付近で↑を押して入室。
- スマートフォン横画面：◀ / ▶を長押しして移動、「入室」をタップ。
- タイトルの「はじめる」→遊び方1画面→「ゲーム開始」→本編。遊び方は毎回表示し、説明中は本編を開始しません。
- 「はじめる」のクリック・タップ・Enter / Returnでチャイムを1回再生し、遊び方・本編への移行でも最後まで継続します。
- 本編の「遊び方」は一時停止。「閉じる」またはEscで再開します。
- END本文はクリック・タップ・Enter / Returnで1行ずつ進みます。
- タイトルのリストやENDの戻るボタンにフォーカスしてEnterを押すと、そのボタンの操作を実行します。

## 進行ルール

クラス番号は進行状態です。長い廊下へ1〜8組を事前配置せず、現在の進行方向へ1クラス分の固定テンプレートを逐次生成します。引き返しても過去の物理ブロックには戻りません。保持するのは現在ブロックと描画用の直前ブロックの最大2つです。

体験順は、プレートなし前扉→窓→窓と向かい合う女子2人→窓→プレート付き後扉→壁の余白→掲示板と男子→柱です。左右どちらへ進んでも同じ順序になります。通常配置とNPCは固定です。

- 1ブロックは3,700px、開始壁ゾーンは900px。主人公全体が壁ゾーン内の境界を抜けたときだけ判断を確定します。
- NORMALなら前進、異変ありなら引き返すことで正解。正解で1クラス進み、誤答で1組へ戻ります。
- ブロック内の方向転換では判断・再抽選しません。通常プレイに正誤のメッセージは出しません。
- 最初の1組だけNORMAL確定。誤答後の1組は通常抽選です。開始地点に下駄箱は表示しません。
- 後扉中央の真上に「1-1〜1-8」のプレートを表示します。

### 8組

8組もNORMAL / 異変の判定対象です。異変を正しく引き返した直後の次の8組だけ、`Run.nextFinalNormal`でNORMALを保証します。生成時に消費し、新規ゲームで解除します。

NORMALの8組へ正しい方向に歩き、後扉の75px以内へ到達すると入室可能になります。↑または入室ボタンでENDへ進み、自動クリアはしません。前方の端では主人公の中心を3,675pxで止め、同じブロックを保持します。扉へ戻って入室できます。

異変のある8組は入室できません。誤って前進すると1組へ戻ります。

## 描画と歩行

論理Canvasは960×440、Retina対応は最大2倍です。背景は`createPattern`による反復描画で、累積ワールド座標へ固定します。蛍光灯も累積座標の400px間隔を維持します。

掲示板の通常画像と「死」の画像は位置だけ反転し、画像自体は左右反転しません。他素材は既存の反転仕様を維持します。割れ窓は通常窓の上へ同じ矩形で重ねます。

プレイヤー停止時は`player_idle.png`、歩行中は`player_walk_01.png`〜`06.png`を順にループします。idleは歩行ループに含めず、停止時に即戻します。全7枚の1600×1600pxを同じ278.64×278.64pxの矩形で描画し、共通足裏アンカー1470 / 1600を足元Y=386へ合わせます。個別トリミング・倍率・アンカー補正は行いません。左向きは同じ画像を水平反転します。

基準フレーム間隔は120msを歩行速度倍率で割った値です。PC・タッチ操作は共通処理で、足音は歩行01 / 04の表示に同期します。

現在の異変はすべて静的です。停止・ポーズ中はCanvasの既存画像を保持し、位置・歩行画像・ブロック・向き・読み込み状態が変わると再描画します。画面サイズ変更と再開でも再描画します。本編の時間管理は描画回数と独立しています。将来、時間で変わる異変を追加する場合は、再描画条件にもその変化を追加してください。

## 設定と異変

数値は`config.js`を編集し、再読み込みしてください。公開変更にはcommit・mainへのpushが必要です。現在の設定値は以下です。変更済みの値を初期値へ戻さないでください。

| 設定 | 現在値 |
| --- | --- |
| `walkSpeed` | 1.2（基準250px/秒×1.2＝300px/秒、歩行1コマ100ms） |
| `anomalyRate` | 0.6（NORMAL40%、異変60%） |
| `anomalyWeights` | 全10種類が1（各異変の通常出現率6%） |
| マスター・カテゴリ音量倍率 | 全て1.0 |
| 基準音量 | 環境音0.12、電灯0.07、足音0.28、引き戸0.40、チャイム0.40 |

異変は床の穴、犬、割れた蛍光灯、こちらを見る女子2人、こちらを見る男子、床の血痕、窓の血の手形、掲示板の「死」、血の付いた包丁、割れた窓の10種類です。1ブロックで1種類だけを選択し、犬やNPCの追加アニメーションはありません。

Dキーでデバッグを開き、次ラウンドの異変を指定できます。「指定状態でこのラウンドを再生成」は進行を変えず現在ブロックを作り直します。初回1組は再生成できません。Dで閉じると以後は通常抽選へ戻ります。`game.js`の`FORCE_ANOMALY`でも固定できますが、通常公開時は`null`です。

デバッグのENDプレビューは全9種類を既存演出で再生し、保存せず元の位置へ戻ります。

## エンディングと保存

全9種類は記憶1〜7、日常、終焉です。文章は`endingData.js`にあり、依頼がない限り変更しません。

1〜7組は、そのプレイで初めて入った教室の順に記憶1〜7を割り当てます。例：3→6→3→2組なら記憶1→2→1→3。誤答しても割り当てを維持し、新規ゲームで割り当てだけリセットします。記憶END後は同じ位置の廊下へ戻るか、タイトルへ戻れます。

全9種の解放状態は`localStorage`の`ichinen8_endings_seen`へ、文字列1〜9のJSON配列で保存します。新規ゲームでも保持し、旧1〜7の保存も読み込みます。記憶ENDは最後の本文の表示完了時、日常・終焉は最後の演出完了時に解放します。

8組への入室時、記憶1〜7の全てが解放済みなら終焉、それ以外は日常です。日常の最後は白いフェード1600ms→一拍800ms→END、終焉は黒いフェード1600ms→一拍800ms→ENDです。

タイトルは「エンディング X/9」。リストは未解放を「？？？？？」として再生不可にし、解放済みのみ本編と同じ演出で再生します。リスト再生は本編進行・割り当て・保存を変更しません。「記憶を消去する」は確認後に解放データだけを消去し、他の保存キーへ触れません。`localStorage.clear()`は使用しません。

## 共有・OGP・PWA

タイトルの共有はWeb Share APIの有無にかかわらず、メール→LINE→Facebook→X→リンクをコピーの順で独自メニューを表示します。メールは`mailto:`、SNSは投稿画面へのリンクです。投稿確定やメール送信は行いません。コピーはClipboard API、旧コピー処理、手動選択欄の順でフォールバックします。

`shareData.js`で共有文とURLを編集できます。固定URLが空なら、現在のURLからクエリ・ハッシュを除去します。OGP画像は`assets/images/ogp_image.png`です。

PWAはHTTPS / localhostで登録し、非対応・登録失敗でも通常プレイできます。アプリ表示は`standalone`、横画面指定です。iOSにはホーム画面への追加案内を表示します。インストールと横向き固定の最終動作はOSに依存します。

`service-worker.js`の現在の`CACHE_VERSION`は`v21`です。公開更新時に版を上げます。主要ファイルをプリキャッシュし、画像・音声は取得時に保存します。オンラインではネットワーク優先、通信失敗時にキャッシュを使用します。旧版の`ichinen8-cache-`だけを削除し、他アプリのキャッシュは保持します。プレイ中の強制再読み込みや`skipWaiting`は行いません。

## 検証

```sh
node --test tests/*.test.cjs
```

ルール、入力・描画、全END、保存、音声、設定、共有、PWAを確認します。DOM / Canvasを代替したテストは実レイアウトや端末の聴感を保証しないため、画面変更時は実ブラウザも確認してください。

別途、localhostの配信中にPlaywrightとChromeでPWAブラウザテストを実行します。

```sh
node tests/pwa.browser.cjs
```

必要なら`PLAYWRIGHT_PATH`、`CHROME_PATH`、`PWA_TEST_URL`を指定してください。PC、Android相当、iPhone相当、アプリ表示、Worker登録失敗、保存・オフライン、遊び方経由の開始を確認します。出力画像は一時フォルダ`ichinen8-pwa-qa`へ保存し、`QA_OUTPUT_DIR`で変更できます。追跡済みの`preview/`は上書きしません。

PC1440×900、スマートフォン横844×390と568×320も必要に応じて確認してください。タッチ・iPhone / Android・アプリ表示のエミュレーションは物理実機へのインストールや聴感確認とは別です。
